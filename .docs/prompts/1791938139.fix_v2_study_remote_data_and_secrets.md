# Request

The user ran the v2 study (`--phase sanity`, then `--phase broad`) on the remote
A100 training host and reported a problem, with the full log. Symptoms:

- `prepare_hpo_split.py` failed with `Input not found: data/processed/train.parquet
  (run the ETL first)`.
- The study warned `Split metadata not found at data/processed/v2/split_metadata.json`
  and proceeded; every trial then failed with
  `FileNotFoundError: Parquet file not found: data/processed/v2/train.parquet`
  and was pruned. Trial #3 was interrupted with KeyboardInterrupt.
- The log shows the full credentialed Postgres DSN printed by
  `init_study_and_metadata` (`storage=postgresql+psycopg://neondb_owner:...@...`),
  and `data/yoda_hardened_v2_*_metadata.json` files were written containing it.

Ask: fix the problem so the study runs correctly on the training host.

## Reasoning

Root cause of the trial failures: `data/processed/*` is gitignored (derived data),
so the training host's clone contains neither the processed parquet inputs nor the
v2 splits — the study's defaults pointed at non-existent files and every trial
pruned. Two code-level defects made this worse: (1) the study only warned about
missing split metadata instead of failing fast, burning trials and wall-clock; (2)
`init_study_and_metadata` wrote and logged the credentialed storage DSN verbatim
into metadata JSON files that land in the tracked `data/` directory — a credential
leak into committable files and logs, violating the telemetry redaction
discipline (workflow.md §3: mask the password component of a DSN).

## Consulted rules

- `workflow.md` — full per-task loop (prompt file, tests, commit, push)
- `workflow.md` §3 (telemetry) — DSN password redaction for logs/metadata
- `best-practices.md` — writing Python
- `workflow-testing.md` — regression tests ship in the same commit
