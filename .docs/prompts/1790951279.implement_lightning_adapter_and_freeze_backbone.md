## Plan
1. Create `src/yoda/training/lightning.py` containing `YodaLightningAdapter(pl.LightningModule)`:
   - Holds `self.model: YodaDecisionEngine` as a pure, decoupled PyTorch module.
   - Implements `training_step`, `validation_step`, `test_step`, and `configure_optimizers`.
   - Computes multi-objective loss: CrossEntropy, FuzzyBelnapLoss, and task-conditioned LTNConstraintLoss with multiplicative scaling.
   - Logs `train_loss`, `train_acc`, `val_loss`, `val_acc`, `val_knowledge`, `val_ltn_loss`.
   - Handles custom batch dicts safely in `transfer_batch_to_device` without breaking non-tensor string types.
2. Export `YodaLightningAdapter` in `src/yoda/training/__init__.py`.
3. Update `experiments/train_yoda.py`:
   - Default text backbone to 100% frozen (`--unfreeze-top-layer` as optional opt-in flag).
   - Add optional `--use-lightning` flag to train with `pytorch_lightning.Trainer` while preserving standard `YodaTrainer` execution.
4. Write unit tests in `tests/test_lightning.py` testing the LightningModule lifecycle (training_step, validation_step, optimizer configuration, and pure model decoupling).
5. Document ADR 0009 covering the decoupled LightningModule adapter pattern.
6. Verify test suite and formatting via `just check`.

## Outcome
- Implemented `YodaLightningAdapter` in `src/yoda/training/lightning.py`, exporting it in `src/yoda/training/__init__.py`.
- Preserved `YodaDecisionEngine` as a 100% pure, decoupled `torch.nn.Module`.
- Updated `experiments/train_yoda.py`:
  - 100% text encoder backbone frozen by default across all 6 transformer layers (~860k trainable parameters).
  - Added opt-in `--unfreeze-top-layer` flag.
  - Added `--use-lightning` flag for PyTorch Lightning training runs while retaining the native `YodaTrainer`.
- Added unit and integration tests in `tests/test_lightning.py` testing steps, optimizers, and fast dev run.
- Documented ADR 0009 (`.docs/adrs/0009-decoupled-lightning-adapter.md`) and updated index.
- All 88 tests pass cleanly with zero linter errors (`just check`).
