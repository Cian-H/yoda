# Request

1. Streamline `justfile`: eliminate low-value 1:1 command abstractions (such as `just install -> uv sync`, `just test -> uv run pytest`, `just lint -> uv run ruff check .`, `just format -> uv run ruff format .`). Keep high-value composite and automation recipes (`check`, `workbench`, `clean`, `check-rules`).
2. Direct agents on appropriate use of available MCPs (specifically `jev` MCP for decision comparisons, baseline benchmarking, and verification, alongside `lsp-servers`, `structural-editing`, `atuin`, `memory`, and `sequential-thinking`).

## Reasoning

- Devenv already automatically syncs `uv` packages on entry (`languages.python.uv.sync.enable = true`), and single-command wrappers like `just test` or `just install` add unnecessary cognitive overhead and indirection without adding value over running `uv run pytest` directly.
- The `justfile` should focus strictly on composite or non-trivial workflows: `check` (linting + testing), `workbench` (interactive Marimo session), `clean` (artifact removal), and `check-rules` (pre-commit trigger validation).
- Yoda is an experimental System 1 decision engine. Having clear MCP directives in `agents.md` and `system1-eval` enables agents to benchmark decisions against Jev (`jev_decide`, `jev_compare`, `jev_verify`, `jev_gate`), leverage structural editing / LSP tools for code manipulation, and utilize sequential thinking for neuro-symbolic logic formulations.
