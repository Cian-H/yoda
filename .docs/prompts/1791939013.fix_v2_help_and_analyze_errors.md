# Request

The user reported two different errors on two different training nodes, both
running the v2 study tooling (logs attached):

- Node 1 (`/content/yoda`): the new fail-fast worked (`train dataset not found:
  'data/processed/v2/train.parquet'. Run ... prepare_hpo_split.py first`), but
  `experiments/analyze_study.py --study-name ...` then crashed with a raw
  `KeyError: 'Record does not exist.'` from `optuna.load_study`.
- Node 2 (`/home/renku/work/yoda`, Renku): `optuna_study_v2.py` crashed at parser
  construction with `ValueError: badly formed help string` (caused by
  `unsupported format character 'D'`), raised from
  `build_base_study_parser`'s `--storage` help f-string; `analyze_study.py`
  crashed with the same `KeyError`.

Ask: fix both errors.

## Reasoning

Two distinct bugs, both surfaced only on remote nodes:

1. **argparse help %-formatting crash.** argparse help strings are rendered with
   `%`-formatting, so a literal `%` in the interpolated `default_storage` breaks
   parser construction. The v2 study passed `resolve_storage(None)` (the
   `YODA_OPTUNA_STORAGE` value) as `default_storage`, and the Renku node's storage
   URL contains percent-encoded characters — so `optuna_study_v2.py` crashed
   before parsing a single argument. The URL also must not appear in `--help`
   output at all (credential leak).
2. **Cryptic analyze failure.** `analyze_study.py` called `optuna.load_study`
   directly; a wrong `--study-name` (or a storage with no such study) raised a raw
   `KeyError: 'Record does not exist.'` with no hint about what exists.

Both nodes also still lack the gitignored derived data — the fail-fast and the
prepare-split error messages now name the transfer step explicitly.
