# Request

Decouple the latent projection layer `self.proj` in `BelnapMultiheadPooledAttention` by providing an initialization toggle (`include_projection: bool = True`) and dedicated forward handling (`return_latent` flag and helper methods `forward_pooled` / `forward_latent`), and configure `YodaDecisionEngine` to instantiate its pooling modules with `include_projection=False` to eliminate over 60 million unused parameters.

## Reasoning

ADR 0005 originally specified a dual-readout contract (`latent, pooled_state`) for `BelnapMultiheadPooledAttention` so that general neural architectures could receive a flattened 1D continuous latent vector $\mathbf{h} \in \mathbb{R}^{B \times D}$. However, Yoda evolved into an end-to-end native Belnap transformer where the reasoning core and decision head operate directly on structured `BelnapState` tuples. Consequently, `YodaDecisionEngine.forward` discarded the continuous `latent` vector (`_, q_state = self.q_mpa(q_emb)`).

When native full embedding dimensions ($D = 1024$ for BGE-large) were adopted in ADR 0014 and probe counts were scaled ($Q = 7$, $C = 14$), the projection matrix $\mathbf{W}_{\text{proj}} \in \mathbb{R}^{(2 \cdot Q \cdot D) \times D}$ ballooned into $14.68\text{M}$ parameters for `q_mpa`, $29.36\text{M}$ for `c_mpa`, and $16.78\text{M}$ for `k_mpa`—over $60\text{M}$ unutilized parameters consuming $240+\text{ MB}$ of dead optimizer state memory in GPU VRAM with zero gradient flow. Decoupling the projection allows `YodaDecisionEngine` to disable it completely while preserving full backward compatibility for standalone MPA users and existing tests.

## Output

- Updated `src/yoda/architecture/attention.py`:
  - Added `include_projection: bool = True` to `BelnapMultiheadPooledAttention.__init__`. If `False`, `self.proj = None`.
  - Added `@overload` signatures and `return_latent: bool | None = None` parameter to `forward`. When `return_latent=False` (or when `include_projection=False` and `return_latent is None`), returns `BelnapState` directly without computing or flattening dual evidence.
  - Added `forward_pooled` and `forward_latent` convenience methods.
  - Raised clear `RuntimeError` if `return_latent=True` is requested on an instance with `include_projection=False`.
- Updated `src/yoda/architecture/engine.py`:
  - Set `include_projection=False` for `self.q_mpa`, `self.c_mpa`, and `self.k_mpa`.
  - Removed `_, ...` discard tuples in `YodaDecisionEngine.forward` in favor of direct `BelnapState` assignments.
- Added ADR `0017-decouple-latent-projection-from-belnap-mpa.md` and indexed in `.docs/adrs/readme.md`.
- Updated and expanded `tests/test_belnap_mpa.py` with tests verifying `include_projection=False`, direct `BelnapState` return, error handling, helper methods, and verified `test_engine.py` parameter count reductions.
