# Request

Transition the architecture from padded choice batches (`max_choices` fixed dimension with active criteria masking) to independent candidate evaluation, where each option is assessed individually as `(query, state, choice)` triplets. Enforce choice-level constraints (like softmax cross-entropy and LTN mutual exclusivity) downstream via grouped state tracking rather than static tensor padding.

## Reasoning

Evaluating choices in a fixed-size padded container forces the model to deal with artificial masking tokens (`-1e9`), introduces static index bias, and encourages relative distractor comparison/elimination heuristics rather than evaluating the absolute truth/knowledge coordinates of each candidate. By assessing options individually:
1. No padding or active masking is required; options have arbitrary arity.
2. Inference is natively parallelizable across any number of candidate choices.
3. The Belnap epistemic representation measures the absolute support and refutation of a single hypothesis.
4. Downstream mutual exclusivity (Softmax, LTN XOR) is applied dynamically across grouping keys (`group_ids`) during training.

## Output

- **Architecture Decision Record**: Authored ADR-0013 (`.docs/adrs/0013-independent-choice-assessment-architecture.md`) detailing the motivation, formalization, and consequences of transitioning to independent candidate evaluation; updated index in `.docs/adrs/readme.md` and marked ADR-0011 as superseded.
- **Single-Candidate Encoders**: Updated `ConstraintEncoder` in `src/yoda/architecture/encoders.py` to directly encode flat `list[str]` candidate sequences.
- **Engine & Head Scalar Mode**: Updated `BelnapDecisionHead` and `YodaDecisionEngine` in `src/yoda/architecture/engine.py` to support `num_choices=1` producing scalar logits, support, refutation, truth, and knowledge coordinates, and dynamically accept `candidates: list[str]` while preserving legacy multi-choice backward compatibility.
- **Collation & Candidate Unrolling**: Updated `collate_decision_batch` in `src/yoda/data/dataset.py` to produce candidate-level triplets (`candidates`, `candidate_queries`, `candidate_states`, `candidate_labels`, `candidate_group_ids`, `candidate_task_scalars`) alongside existing batch metadata.
- **Grouped Loss Formulations**: Updated `FocalLoss`, `MarginLoss`, and `FocalMarginLoss` in `src/yoda/training/losses.py` to accept `group_ids` and evaluate grouped cross-entropy and margin ranking across candidate groups.
- **Grouped LTN Mutual Exclusivity**: Updated `LTNConstraintLoss` in `src/yoda/nesy/ltn.py` to compute group-wise XOR semantic loss using `group_ids`.
- **Trainer & Lightning Integration**: Added `independent_eval` mode to `YodaTrainer` (`src/yoda/training/trainer.py`) and `YodaLightningAdapter` (`src/yoda/training/lightning.py`), validating grouped loss and metric calculation on real Parquet batches.
- **Comprehensive Test Suite**: Added `tests/test_independent_eval.py` covering candidate unrolling, grouped focal and margin losses, grouped LTN constraints, and independent engine forward and trainer steps. All 114 tests passing cleanly.
