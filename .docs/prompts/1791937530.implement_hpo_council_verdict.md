# Request

"Ok, do this. Though, do bare in mind this wont be running on the A500. It will
be on far more capable GPUs. Please implement all of your recommended measures,
and then report back to me."

Implements the council-of-five verdict of 2026-10-14 on the appropriate
conditions for the next hyperparameter optimisation experiment: data protocol,
metric, search space, and study mechanics.

## Reasoning

The M1-M4 hardening and the Nimble target fix landed after every existing
Optuna study finished, and the council established that the old objective was
compromised at the data layer (single-source eval slices, 53.8% contaminated
`eval.parquet`, a const-predictor plateau). The user asked for all recommended
measures to be implemented. The GPU note changes one infrastructure decision:
the study will run on more capable GPUs than the local 4 GB RTX A500, so the
distributed Postgres path stays available (env-var storage, multi-worker)
rather than the sqlite-only default the A500 would force. No credentials are
committed — the remote connect string lives only in the run command shared in
chat.

## Consulted rules

- `workflow.md` — full per-task loop (prompt file, ADR, telemetry, commit, push)
- `workflow.md` §2 (ADR) — new modules/pattern/dependency (scikit-learn) and a
  decision with recorded trade-offs
- `workflow.md` §3 (telemetry) — new/changed code paths in the trainer, collator,
  datasets, and harness
- `best-practices.md` — writing Python (type hints, 100-char lines, ruff format)

- `workflow-todos.md` — deferrals captured under `.docs/todos/`

## Output

- Gate 0: `experiments/prepare_hpo_split.py` — group-disjoint, source-stratified
  v2 splits with split metadata; ran on real data (`data/processed/v2/`).
- Gate 1: macro-averaged per-source eval accuracy (`macro_accuracy`) plumbed
  through both datasets, the collator, and the trainer; `history.json` records
  it per epoch; collapse pruning keys on it; `run_training_trial` gains
  `metric_agg` (`final`/`best`/`mean_last2`) plus audit user attrs; the shared
  study parser gains `--eval-path`/`--test-path`.
- Gate 2: `experiments/optuna_study_v2.py` — full realigned search space,
  `min_lr` wired to `lr/100`, explicit runtime/paths (no CLI defaults),
  in-bounds warm start; `logit_scale` exposed through the engine and a
  `--logit-scale` CLI flag.
- Gate 3: phased study (`sanity`/`broad`/`focused`/`validate`); local sqlite
  storage by default with a `YODA_OPTUNA_STORAGE` override (no secrets in the
  repo); `experiments/analyze_study.py` (fANOVA importances + Phase-B/C/D
  exports); `scikit-learn` added as a dependency.
- Retired `experiments/optuna_study_focused.py` and `optuna_study_narrow.py` to
  `experiments/retired/` (tests to `tests/retired/`); changelog updated.
- Tests: `tests/test_hpo_split.py`, `tests/test_macro_accuracy.py`,
  `tests/test_optuna_study_v2.py`, `tests/test_logit_scale.py`, plus extensions
  to `tests/test_hyperopt.py`.
- Verification: `ruff check` and `ruff format` clean; 448 unit + 74 e2e tests
  pass; smoke runs of the split builder, the study CLI (all four phases), and a
  real-Optuna enqueue check (zero out-of-range warnings).
